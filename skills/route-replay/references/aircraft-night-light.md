# Aircraft-only cinematic night lighting

This feature is supported only by the globe renderer’s isolated Cycles aircraft pass. The experimental chase preview uses a shared aircraft/environment scene and rejects positive `aircraft_night_light` values. Set this style to 0 in a separate chase configuration; adding unlinked SUN lights there would also brighten the surroundings.

Set `style.aircraft_night_light` to **1** for a readable cinematic aircraft at night. It defaults to **0** (exact opt-out); accepted strengths are 0–2. This is an artistic lighting rig, not measured lunar photometry and not a new shared lunar multiplier. Keep `style.moonlight` unchanged to preserve the globe's existing light.

The isolated transparent Cycles aircraft scene receives a soft directional key and weaker opposing fill. Both cast mesh self-shadows. At strength 1 their peak scene-relative incident RGB values are respectively (0.12, 0.14, 0.18) and (0.025, 0.03, 0.04), before the twilight fade. The source colours are deliberate cool-neutral creative choices. The dated topocentric Moon direction is used when it is sufficiently elevated and the existing incoming lunar light is useful. Smoothstep confidence over lunar elevation sine 0–0.25 and incoming peak RGB 0–0.001 blends that direction toward a fixed camera-relative upper-side key (−0.48, −0.36, 0.8) otherwise. The fill direction is (0.6, 0.2, √0.6). Thus a dark, eclipsed or hidden Moon does not make the aircraft disappear, but the fallback is explicitly artificial. Setting shared moonlight to zero also selects this fallback.

A separate smoothstep fade reduces both lights from full strength at a local Sun altitude of −12° to exactly zero at −2°. It is stateless, frame-order-independent and based on physical UTC Sun geometry. It does not adjust solar irradiance, the real lunar light, materials, camera, exposure, or existing environment lighting. The transparent aircraft pass is the only consumer. Terrain, ocean, globe, atmospheric/cloud radiance and extinction/density are untouched. Normal depth/coverage compositing and foreground cloud/air transport remain in effect: it cannot expose an aircraft hidden behind opaque clouds or terrain.

Trip style participates in final and HDR scene cache identity. Prepared lighting samples carry the strength, and the Cycles deduplication key includes all four cinematic light vectors. Source changes invalidate the enclosing render cache. Do not point a manually changed sample file at previously rendered aircraft files; use the CLI's new configuration cache.

## Verification

`tests/test_aircraft_night.py` checks exact default/day zero, gain bounds, lunar/fallback behavior, monotonic twilight fade, unchanged transport attenuation and serialized trip configuration. Render matched pairs with only this style changed and identical quality, dates, assets, seeds and exposure. Confirm equality outside aircraft coverage, identical alpha/depth and an increased aircraft luminance. Also compare a daytime pair; the light state must be identical, allowing only independently measured Cycles/denoiser repeat-render noise. This feature is intended for the 3D Cycles mode; diagram mode cannot validate its lighting or materials.
